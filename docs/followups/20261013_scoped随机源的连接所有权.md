# scoped 随机源的连接所有权

## 问题与现状

正常 scoped 网络资源图尚未闭合随机源。`russh/src/keys/key.rs::safe_rng()` 和部分 KEX 算法使用 `rand::rng()`；其线程局部 `Rc` backing 由线程及其他 RNG holder 共享，不能在单个连接结束时释放或退还预约。

锁定的 `rand` 实现不保证 `ThreadRng` 状态在析构时清零。现有协议缓冲和 crypto-bigint 的局部秘密擦除证据不能替代该随机源的所有权、擦除与实际释放证据。这里的 TLS 指线程局部存储，不是 TLS 协议栈。

既有 `getrandom` 提供向调用者 buffer 填充随机字节的可失败入口；其 Rust 调用部分未显示独立 heap backing，但各目标的系统熵源及原生资源生命周期仍须区分核验，不计为零，也不挪用 SQLite 配额。

错误封装也属于资源图。`std::io::Error::other` 及无 OS 错误码时的 `getrandom::Error` 转换带入 owned error payload，不能视为零分配；仅保留 `ErrorKind` 会丢失部分原始错误身份，须核对 typed operation/resource 交付要求。

锁定的 ML-KEM 未启用其 `zeroize` feature。可失败生成分两次填充种子，第二次失败时第一份临时种子没有自动 Drop 擦除保证；协议缓冲的擦除不能替代这个中间值和最终密钥对象的清理。

## 下一步与验收

在既有 russh scoped 接缝内核对并接入可受控的随机源，使调用前准入、真实 holder、秘密擦除、最后 dealloc 与退款覆盖实际 KEX 和后续随机字节调用。必须保留密码学安全强度及必要的重新播种行为；随机源失败须正常终结并与资源准入失败区分，不能输出占位随机字节或用 panic 代替错误交付。

Curve25519 保持现有 32 字节采样与 `from_bytes_mod_order` 语义。ML-KEM 的临时种子须在填充失败时完整擦除；受控完整种子与公开 `from_seed` 接缝仍需核验成功路径的全部秘密副本、最终密钥析构和各目标证据。错误交付不得依赖字符串匹配或共享 last-fault 状态。

旧公开入口、认证与信任语义保持不变。不能仅改 KEX cookie 或增加孤立 RNG helper 后签收正常连接；全部调用点及目标证据闭合前，生产 V2 仍关闭。当前没有新增依赖 fork 的授权或必要性证据。
