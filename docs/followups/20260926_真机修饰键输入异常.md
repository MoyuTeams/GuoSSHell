# 真机输入链路的修饰键事件滞留

## 问题

设备输入链路异常时，App 窗口没有收到独立的修饰键按下与松开事件，后续普通字符仍带有上一组 Ctrl / Option 状态。
相同现象也能出现在系统原生输入框中，因此不能仅由终端接收的字节判断为终端编码问题。

## 现状

当前设备已能交付完整的 Control 按下与松开事件，松开后的普通文本不再带残留修饰位。
镜像测试会话已关闭，实体键盘连接正常；这两个因素尚未分别做隔离复现，具体触发条件仍未确定。
全键盘控制和粘滞键均经只读检查确认为关闭。

App 保留标准 Flutter 硬件键盘和输入法路径，没有额外注入全局修饰键状态。
最终代码上的真机原生回归通过：Ctrl+[、Option+x、Shift+Tab、Option / Control / Shift 点击、
Command 缩放快捷键，以及松开修饰键后的普通输入。

实体滚轮已有正确远端记录。中文选词与取消的精确交互尚未完成验收，现有证据不构成中文丢字的判断。

## 下一步

单独复验镜像会话启停、键盘热插拔及系统输入链路，保留窗口层原始事件证据以定位触发条件。
验收时同时核对修饰键释放后的普通文本，避免只验证组合键本身。
继续补验完整中文选词、提交与取消。
