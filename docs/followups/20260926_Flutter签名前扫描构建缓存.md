# Flutter 签名前扫描构建缓存

## 问题

iOS 构建准备会递归清理项目目录的扩展属性，Rust 构建缓存和本地 fork 工作副本也在扫描范围内。
这些目录不会直接打包进 App，扫描却可能持续数分钟，并显著增加主机负载。

## 现状

源码、资源和 App 产物仍需要正常执行签名前清理；当前 Flutter 的目录排除没有覆盖 Rust 缓存和本地 fork。
这会影响真机测试的启动时间，不能算作 App 的运行性能问题。

## 下一步

核对 Flutter 上游的排除机制，评估将不参与 App 打包的缓存移出扫描范围，或向上游补充可配置排除项。
验收时同时确认签名成功、产物完整，以及构建准备耗时。
