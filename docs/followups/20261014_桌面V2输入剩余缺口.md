# 桌面 V2 Flutter 输入的剩余缺口

## 问题与现状

桌面三平台的终端窗格经有序通道把 Flutter 的按键、文本与鼠标事件交给 Rust，终端
profile 在 Rust 侧生效。以下情形仍未按 profile 完整处理：

- AltGr 与 macOS Option 组合字符：渲染库在 Alt 按住时把按键交成「键 + Alt」，
  不带布局产生的字符。profile 不把该侧 Alt 当作 Meta 时，Rust 拿不到应输入的字符。
- 不带 Ctrl/Alt 的可打印键经平台文本输入以文本提交，不产生 Key 事件，
  Kitty/CSI-u 的按键与释放编码不覆盖这类键。
- 数字小键盘的 +/- 缩放组合在渲染库中没有对应键名，不会到达 Rust，也不触发缩放。
- 渲染库处理按键后会在本地把视图跳到底部。窗格把这一跳识别为非用户滚动并回到
  Rust 给出的视口，按键是否回到底部由 profile 决定；滚动条恰好拖到底与按键后的
  跳底仍无法区分。
- 键位条在 V2 窗格中使用通用键位条，挂住的修饰键没有物理来源，Alt 来源按未知上报。

## 下一步

在渲染库键盘事件中补充按键产生的字符（或在 Alt 不作 Meta 时把按键交回文本输入），
再由 Rust 按左右 Alt 的 profile 选择编码；为小键盘缩放补键名；在渲染库提供关闭
按键后本地跳底的开关，替代窗格内的识别。
