# macOS：键盘与菜单、签名构建待验证

- 状态：待验证（非阻塞）
- 记录日期：2026-09-26

## 问题

macOS 版在本机 debug 构建上验证了连接、渲染、私钥与登录，但以下几项需要人在 Mac 上操作，
自动化无法代劳（没有模拟键盘、触控板与菜单的权限）：

1. **键盘与菜单**：Flutter 模板的主菜单带「拷贝 ⌘C」「全选 ⌘A」「粘贴 ⌘V」。终端里的这几个
   快捷键要走引擎（复制选区、全选含滚回、粘贴经 bracketed paste），需要确认按键先到 Flutter、
   而不是被菜单直接处理；⌘T 新标签、⌘W 关窗格、⌘D / ⌘⇧D 分屏、⌘1…9 切标签也要试一遍。
2. **触控板与鼠标**：滚回的双指滚动与惯性、选区拖拽、htop 等程序的鼠标上报、窗口缩放后终端
   重新排版。
3. **OpenPGP 卡**：macOS 上经 CryptoTokenKit 读 USB 卡（需要 `com.apple.security.smartcard`，
   已在 entitlements 里）；GnuPG 的 scdaemon 占着卡时读不到。
4. **带团队签名的构建**：有钥匙串访问组时私钥存进 protected data 钥匙串、可以开 iCloud 同步；
   从 ad-hoc 构建换到签名构建后，登录钥匙串里已有的私钥不会自动搬过去。

## 现状

- 本机 ad-hoc 签名的 debug 构建：连接、m1bar 60 Hz、滚回、登录钥匙串存取私钥、私钥登录都已跑通。
- 若 ⌘C 等被菜单拦下：把模板菜单换成 Flutter 的 `PlatformMenuBar`，菜单项回调走引擎的复制 / 全选。

## 下一步

1. 按上面四项在 Mac 上走一遍，记录不符合预期的按键或操作；
2. 键盘被菜单拦下时改用 `PlatformMenuBar`；
3. 签名构建上决定是否把登录钥匙串里的私钥迁移到 protected data 钥匙串（或提示重新导入）。
