# SSH 会话不发送 LANG

- 状态：待决定（产品）
- 记录日期：2026-09-26

## 问题

OpenSSH 客户端默认把 `LANG`、`LC_*` 发给服务器（`SendEnv`），Debian / Ubuntu 的 sshd 默认接收
（`AcceptEnv LANG LC_*`）。GuoSSHell 的 SSH 通道不发送任何环境变量：服务器没有配置系统默认
locale 时（精简镜像、容器开发环境、部分云主机镜像），会话是 POSIX locale——btop 这类要求 UTF-8
的程序直接拒绝启动（「No UTF-8 locale detected」），其他程序的中文输出、中文文件名也可能变成
转义或问号。

## 现状

- M6 验收（docs/acceptance-m6-2026-09-26.md）中发现：验收容器配上系统默认 locale 之后 btop 才能运行。
- 上游 rsHell 的 native_ssh 传输没有发送环境变量的入口。

## 下一步

1. 决定发什么：与 OpenSSH 一致按设备语言发 `LANG`（如 `zh_CN.UTF-8`、`en_US.UTF-8`；服务器没生成
   该 locale 时程序退回 C 并告警），或只发 `LC_CTYPE=C.UTF-8` 保证 UTF-8；是否放进连接设置可改。
2. rsHell 补丁：传输层在请求 PTY 之前发 env 请求（russh `set_env`）；设备语言由 Rust 按平台取。
