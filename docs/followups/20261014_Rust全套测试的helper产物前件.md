# Rust 全套测试的 helper 产物前件

## 问题与现状

Windows 的 `selected_p1_helper_artifact` 验收需要通过
`SELECTED_HELPER_ARTIFACT_DIR` 提供真实受证候选，包含来源 recipe、产物记录与 helper
映像。普通源码检出或暂存树导出不能替代这些材料；未提供候选时，全 workspace 测试
会在 fixture 初始化阶段失败，不能登记为全套通过。

候选必须符合现有来源、编译器、目标、依赖 features、摘要及大小校验。普通 GNU 构建
不能冒充指定的 MSVC 候选，缺少授权来源根时不得自动生成或复用未知产物。

同一测试目标中，容量审计单项用例通过，但其并行稳定性尚未证实。正常桌面输入的
局部及组合证据不替代这项实验验收，也不证明全 workspace 测试稳定通过。

## 下一步

在明确授权的来源根和精确输入清单上，使用现有构建入口生成可核验候选，再配置验收
环境并执行全套测试。核对容量审计与其他并行用例的共享状态，保留有效断言，不以忽略
测试、关闭全套并行或放宽产物验证取得通过。

这项实验验收不作为正常桌面生产接线的来源闭包前件；桌面生产开放仍按其自身的实际
输入、认证、生命周期和平台验收条件执行。
