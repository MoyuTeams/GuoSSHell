# 桌面键盘同源与同步仲裁接缝

## 问题

桌面有序 Key 的真实生产消费者尚未接通。Flutter 公共 `KeyEvent` 不含原生事件 ID，`character` 在 Ctrl、keyup、dead key 和 IME 场景下可为空，`logicalKey` 不能跨平台证明当前布局的未移位字符。按物理码、phase、时间戳、FIFO 或最近事件拼接另一通道的原生元数据，不能证明同事件来源。

## 现状

- 独立 Rust 输入策略已验证绑定优先级、消费锁存、repeat/release 和编码行为，但调用方仍须证明 raw chord、双表示、物理身份、AltGr 和文本排他来源。
- 三个桌面 runner 尚无相应来源适配器；现有 GUI 默认动作和终端输入入口仍需纳入 Rust 先仲裁的链路。
- 原 US Shift 适配表不能用于推导非 US 布局。资料中的平台查询 API 不等于本应用已经实现或实测通过。
- 同步 GUI／原生输入与异步 Rust actor 之间的 disposition、焦点 owner 和文本提交关系尚未证明。生产接线保持停止，缺来源时不得猜码或放行默认动作。

## 下一步

已获准先验证有限原型：仅本应用终端区域内的单一原生键／IME／指针来源、应用私有非阻塞同步 Rust 仲裁，以及 V2 owner 绑定撤销、统一顺序和文本／粘贴票据。按计划审查后实施，先证明线程与队列边界、真实 engine owner、焦点与 generation 终结、迟到文本拒绝及旧客户端关闭关系。原型未验证前不启用生产。

关闭旧键／文本入口须同时保留鼠标报告、选区、剪贴板和候选窗；不能用陈旧的 Flutter 修饰键状态补原生指针事件，也不能仅开启 `readOnly` 后丢失鼠标功能。

不得采集认证／密码字段或其他窗口，不启用全局键盘监听或额外系统权限，不将 P1 控制入口扩大为键盘入口。保持移动及桌面 V1、认证与 trust 不变。完成三平台非 US、dead key、AltGr、IME、repeat/release 和焦点切换的真实验收后，才能解除该停止线。
