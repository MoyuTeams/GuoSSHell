# 真实系统熵错误验收边界

## 问题与现状

风险等级：低，属于真实系统故障覆盖缺口，未证明当前正常熵源或错误处理存在安全缺陷。深层 typed 熵错误与全资源验证延至本分支之后；应用保持系统随机源和失败收口，不强造 errno，也不以此阻塞正常功能接线。

scoped 熵错误通道仍缺真实系统失败从实际采样到公开连接／重键出口的运行证据。自定义错误、内部错误原值及部分采样失败的局部测试不能替代这项覆盖。

SDK 锁定的 `getrandom 0.4.3` 使用平台相关 backend：

- Windows 调用 `ProcessPrng`，失败映射为无 OS code 的 `UNEXPECTED`；该路径不提供 `raw_os_error=Some(...)`。不得为满足测试形状伪造 errno 或改写原始错误。
- Linux 的真实 `getrandom` 系统调用失败可以保留 errno。隔离测试进程的 seccomp `EIO` 拒绝可用于核验系统调用失败映射链，但尚未实际运行；这不是内核熵源自然故障的证明。初始化探测可能对 `EPERM` 启用 fallback，不能据此假定采样必然失败。
- macOS 的 `getentropy` 失败映射保留 errno，但有效缓冲区下的确定性真实失败触发及运行证据尚未取得。伪造 libc 返回值或 errno 不算真实 OS 失败。

现有计划要求可取得真实 OS 错误时核对原值与 `raw_os_error`，不可取得时保留覆盖缺口；三桌面的正常路径、资源布局与运行验收仍须分别完成。

## 分支后下一步与验收

在可用 Linux runner 的隔离测试进程中，先建立受控系统调用拒绝，再让实际 `RandomBelowOperation` 调用真实 `SysRng`，核对原始 OS 错误到初次连接及重键终态的 source、phase、generation 和 site。保留首错、错误交付无新增分配、部分秘密擦除、晚持有者与最后 free 后退款的要求。

过滤只作用于任务拥有的测试进程，不扩大权限、不影响其他进程，不安装工具或改变生产 backend。平台不支持的错误形状与未执行场景必须如实报告，不以自定义错误、私有字段、transmute 或有损转换补齐。此项未完成前不得据局部错误通道测试签署完整网络资源图。
