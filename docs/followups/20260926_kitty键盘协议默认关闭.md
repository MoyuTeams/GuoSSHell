# kitty 键盘协议默认关闭

- 状态：待决定（产品）
- 记录日期：2026-09-26

## 问题

引擎的 kitty 键盘协议（`CSI > flags u` 推送、`CSI ?u` 查询）默认关闭，App 也没有打开它。
在传统编码下 Shift+Enter 与 Enter 都是 CR，Ctrl+I 与 Tab、Ctrl+[ 与 Esc 也分不开：

- Codex 不查询、直接推送 kitty 标志，推送被忽略后按传统编码处理，Shift+Enter 换行不可用；
- opencode 查询 `CSI ?u` 没有应答，同样退回传统编码；
- Claude Code 也查询 `CSI ?u`。

多行输入只能改用各 agent 的替代换行键（如 Ctrl+J），与桌面终端的习惯不一致。

## 现状

- 上游 rsHell 已实现该协议（查询应答与按标志编码按键），但设置项默认关闭，hub 也没有打开；
  关闭时引擎忽略推送、不应答查询。
- M6 验收（docs/acceptance-m6-2026-09-26.md §8）的 agent 与 iPad 键盘用例都在传统编码下进行。

## 下一步

1. 决定是否默认打开，是否放进连接设置可改（rsHell 本身有按连接覆盖的设置项）。
2. 打开后重跑 M6 的 D 类（iPad 键盘）与 agent 用例：确认各 agent 推送 / 弹出标志后按键编码正确，
   退出 agent 后回到传统编码，Shift+Enter 在三个 agent 里换行。
