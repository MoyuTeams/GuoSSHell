# 安全密钥的 RP ID 与真机验收

- 状态：待决定 + 待验证（非阻塞）
- 记录日期：2026-09-26

## 问题

iOS / macOS 的 AuthenticationServices 只接受 App 经 Associated Domains（`webcredentials:`）
关联的域名作 WebAuthn 的 RP ID，安全密钥请求也一样。OpenSSH 默认的 application `ssh:` 不是
域名，系统直接拒绝（`ASAuthorizationError` 1004，说明为 App「not associated with domain ssh:」）。
所以安全密钥上的 SSH 密钥只能用一个关联域名作 application；`ssh-keygen -t ecdsa-sk` 在别处
生成的 `ssh:` 密钥在 App 里用不了。

## 现状

- RP ID 取 Info.plist 的 `GUOSHSecurityKeyRelyingParty`，现为空：构建不提供安全密钥，
  「私钥」页不出现「添加安全密钥」。
- debug 构建的模拟安全密钥（`GUOSH_VIRTUAL_SECURITY_KEY`）不受这条限制，`ssh:` 与域名两种
  application 都已在模拟器上登录测试容器；OpenSSH 服务器不限制 application。
- 系统路径只在模拟器上跑到了被拒这一步，没有在真机上用过真的安全密钥。

## 下一步

1. 选一个可控的域名作 RP ID（产品决定）；
2. 在该域名的 `/.well-known/apple-app-site-association` 的 `webcredentials.apps` 里加上 App ID，
   签名配置开启 Associated Domains，加 `webcredentials:<域名>`；
3. Info.plist 的 `GUOSHSecurityKeyRelyingParty` 填这个域名；
4. 真机上用 FIDO2 安全密钥（USB-C 直插、NFC 各一次）添加、授权公钥、登录；macOS 随 M5 再验一遍。
