# 桌面检查点待完成验收

## 问题与开放边界

本批次提交是桌面检查点，不代表功能完整交付。阶段四输入、阶段五设置、Local Shell、隔离 System SSH 与最终验收仍需完成生产接线及 Windows、macOS、Linux 的构建、测试、GUI 与适用沙箱验证。正常 Prepare、Start、VM 最后持有者与全目标资源预算尚未验收，独立单元通过不能替代这些证据。

新 V2 的 `Preparations::default()` 关闭准备机制；`begin`、`start` 在预算预约、解析、消费准备态或启动会话之前返回 `PolicyUnavailable`，只有测试专用构造器开启。未验收能力保持关闭，旧 Native、桌面 V1 与移动端保留原行为。这是新路径的验收守护条件，不是将正常配置、字体或 Start 永久拒绝的产品目标。

## 当前证据与限制

- **P1 单元：** 配置解码、字体来源、控制、helper、受证候选读取及网络资源根已有独立验证；实际配置图、准入前件和完整生产调用链仍须组合验收。
- **阶段四：** Rust B 的 ABI 3／11 个导出尚未接入正常 actor 和原生宿主。旧 ABI 2 的同 SDK 合成 fixture 只证明指定候选的闭环，不证明 ABI 3 已联调。Windows C 的 415 项 TSF 检查仅覆盖合成消息；真实物理键、非美式布局、死键、TIP、AltGr、IME、鼠标、GUI 动作及三桌面验收仍未完成。
- **阶段五：** 独立设置表单、键位条与资源区已测试；全局字体的 RID／slot／操作确认、无 RID 写入的全应用单写者及未知结果核实、真实原生焦点、关闭期间的租约和 Rinf／SQLite 重开尚未完整接入。
- **Local：** Windows 测试专用路径的 43 项检查包含 TERM、几何、Unicode、自然退出和 8 MiB 堵写取消。完整进程与环境源界、子进程树、持久失败的有限收敛、GUI 及 macOS／Linux 沙箱尚未签收。
- **System：** 私有 helper／scope 覆盖受控 ORDER 回调、负向身份及资源检查；实际握手密钥、持久信任、强制 ASKPASS、秘密跨进程身份链、认证成功和 PTY 仍须三平台完整验收。不得直接启用继承用户配置／agent 的旧 System 路径。
- **网络：** 团队 russh 的显式实验 scoped 入口已有资源、时钟、协作取消、PTY 与认证证据，旧构造器保留原行为。完整运行图仍有 crypto／MAC、压缩、RNG／TLS、错误、服务器发起 channel、公共 bytes 和外部持有者等未闭合范围。crypto-bigint 的 boxed RSA CRT 最后持有者擦除已有独立验证，不代表全部私有密码运算或正常网络资源图已闭合。

## 下一步与签收条件

恢复工作时，按上述守护条件继续接线，补齐输入、设置、本地与隔离 SSH、正常网络资源／认证图及最终三平台的实际证据。新能力只有在对应正常路径、资源与认证边界完成验收后才能开放，并须保持旧接口兼容。

正式 release 与 P1 `SourceClosed` 的签收不能以检测峰值或 SDK root 传输成功代替真实认证及完整运行图证据。三桌面的构建、测试、GUI 与适用沙箱结果必须覆盖实际交付路径；限定 fixture 和独立单元证据只能支持其已验证范围。
