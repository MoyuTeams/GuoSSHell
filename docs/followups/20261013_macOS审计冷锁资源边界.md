# macOS 审计冷锁资源边界

## 问题与当前边界

风险等级：低，目前属于资源证书和审计覆盖缺口，未证实产品内存不安全。底层冷锁零隐藏 heap 与 inline 同步证明延至本分支之后；实际死锁、崩溃或取消失效不在延期范围。普通功能测试与完整资源审计须分别报告，不能预热或接受部分报告来伪造证书。

macOS 桌面 CI 的部分资源测试因 allocator 审计不完整而失败。实际首次重入来源尚未确定，不能以模型结果认定根因，也不能返回部分事件作为资源证明。

新增首次失败诊断只保存固定字段，不分配、不加锁；但既有事件记录仍调用 `ProcessLedger::snapshot()`，其内部使用 Mutex，因此整个 allocator 审计调用链并非无账本锁。已核对的 Darwin Mutex 实现存在首次锁定时初始化外置 backing 的路径；该冷分配的实际来源、所有权与资源准入仍须目标化证据，不能凭内联对象尺寸计零。

## 分支后下一步

利用真实 macOS 运行的首次失败 reason、phase、外层与嵌套 allocator 种类及 Layout，区分审计记录重入、底层 allocator 调用和产品冷锁分配。按实际来源闭合调用前准入、真实持有者及最后释放，不预热隐藏产品 allocation，不过滤事件，不扩大记录容量或放宽完整性断言。完整 macOS 资源证书保持未签。
