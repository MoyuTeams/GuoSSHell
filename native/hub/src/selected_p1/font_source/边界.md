# W1-F 字体源接口与证据边界

本模块提供可执行的借用检查、完整字体绑定元数据与受额度约束的 SourceBody。只通过独立 integration executable 链接；正常 lib/Prepare 尚未注册。GNU 私有 inspection 的源闭包不等于完整 SourceClosure；normal class 仍保持未获证、关闭准入。

## 构建与有限调用

实际 GNU Rust 1.98.1 compiler commit 为 `48a229ceaefd4985c50990b14116b6d856af0985`。`metadata.resolve.nodes.features` 中 ttf-parser 0.25.1 为 `apple-layout/default/glyph-names/opentype-layout/std/variable-fonts`，没有 `gvar-alloc`；sha2 0.11.0 为 `alloc/default/oid`。父必须从实际 compiler/resolve/cfg 提供构建值，常量不自行发现 SDK。`FontBuildProof::verify` 只核验构建前件；`closure::FontInspectionProof::verify/inspect` 的 checked marker 仅覆盖本节的借用检查，不签发完整 Source 或 normal Source 证书。

生产路线为 size≤32 MiB、借用 ASCII 后缀、`00010000/true` signature → `RawFace::parse(bytes,0)` → `0..table_records.len()` 的 `get(index)` → 九个借用 `RawFaceTables` 字段 → `Face::from_raw_tables` → 原 glyph/glyf/cmap 判定、名字和 SHA256。signature 已排除 TTC；目录没有 iterator 累计游标。record offset/length 转目标 usize，checked 求 end 后从原 bytes 取 window；按原目录次序最后匹配覆盖，包括越界 `None`、必需表空 slice 和有效 `Some(空)`；求和失败跳过该项。GNU 两个 u32 的和可表示，其他 target 仍需独立核验。没有排序、去重、binary search、字体字节重写或额外 count cap。

仅提供 `head/hhea/maxp/loca/glyf/cmap/name/fvar/gvar`。必需表错误顺序为 head→hhea→maxp；loca/glyf/cmap/name 的 Option 判定沿 SDK 原语义。fvar 保留默认零坐标长度 `min(axes.len(),64)`，gvar 保留默认 outline 的优先级；生产不主动 outline，也不额外要求 glyph lookup/outline 成功。其余 table parser 不参与本业务，不因其数据损坏而拒绝字体；原始全输入仍参与 hash 和最终 Source copy。正常构建的 Face 仅活在私有检查中，不对其他消费者导出通用 Face；`#[cfg(test)] face_for_qa` 只供独立 executable 复用同一构造函数。

`closure::PARSE_CALLS` 枚举全部实际初始调用、标量 FromData、Stream、LazyArray 与名字/SHA 子调用。下面是 read 发生前的窗口上界，不是按成功 slice 长度反推，也不是新输入限额：

| 路径 | offset＋读取长度上界与前件 |
| --- | --- |
| sfnt/record | `12+16*65535=1048572`；最大 get index 为 65534，record 内部固定 16 bytes |
| head/hhea/maxp | 固定头分别≤54／36／6；保 units-per-em、index format、version、NonZeroU16 |
| loca→glyf | 原 count+1 特例、actual_total 的 u16 转换与 min；Short／Long≤131070／262140；glyf 初始 parse 只保存借用 |
| cmap | `4+8*65535=524284`，仅 EncodingRecord LazyArray，不访问 subtable |
| name v1/storage | lang count checked 乘 4≤65532，`8+65532+12*65535=851960`；storage 定位推进到当前 offset 与 u16 storage offset 的较大者；Names::get 的 offset＋length≤131070 |
| fvar | u16 axes offset＋20-byte axes array≤`65535+20*65535=1376235`，new_at 先核对实际 bounds |
| gvar shared tuples | new_at 先约束 offset 到实际 table≤33554432；checked u16 count product 的 F2DOT14 array≤131070，终点≤`33685502<u32::MAX` |
| gvar offsets/data | 主头 20；glyph count checked 加 1 后 offsets 终点≤262160；variation data offset 通过 slice.get，不先无界 advance |

这些窗口在 u32 与 GNU usize 内，排除生产可达路径中的输入算术 panic；正常及 Option/Result 错误返回的辅助 heap Layout 集合均为空。NamesIter 先 index<len 再递增，最大 65535 安全；坏 record 的 None 停止当前 find_map。名字适配完整解码 UTF16 tail，odd 尾忽略，invalid 候选继续，合法空/全 control 为 Some；非 control 输出至多 128 scalar／512 UTF8 bytes。basename 采用旧 rsplit 借用语义，不调用 Name::to_string、owned lower-case 或中文 owned 错误。SHA256 使用固定 core/block/output、CPU dispatch 与 64-byte hex 栈数组，覆盖完整原 bytes，不调用 DynDigest/alloc API。

独立 allocator audit 只围住预先准备 fixture 后的新借用检查/构造，覆盖成功和错误；项目真实字体、真实 cmap/glyf 三角形 sfnt、variable 默认坐标、65535 条目录、有效/业务忽略的 optional 数据、sbix 极大 count、最大 name v1/record/storage、完整非法 UTF16 tail、odd/空/control/坏 record、检查顺序与窗口错误均验证零辅助分配。没有捕获 panic 或关闭生产 debug/overflow checks。单依赖关闭这些 checks 的旧 route 对照只提供旧语义 oracle，不是完整 release build 证据。

语义 QA 与生产闭包分开：`closure::QA_CALLS` 列实际 fixture 的 `glyph_index→SubtablesIter/get`（项目 glyph A 为 format4，合成为 format0）、`glyf.bbox→get→loca.glyph_range→LazyArray get→固定10-byte头`、`global_bounding_box→head`、`outline_glyph/glyph_bounding_box` 的 glyf simple points 或优先 gvar/default coordinates/空 variation window。QA 比较完整 glyph 数量、mapping、Rect、outline segments 和默认 coord 长度；其 Vec 与惰性 getter 位于 inspection audit 外。这些有效 fixture 结果不证明任意 malformed cmap/outline 的闭包；不调用 set_variation、shaping/bitmap 或其他被裁 table getter。新增生产 API 调用必须先补相应源闭包。

oracle 通过原 fonts/font_resources/profile_fonts 文件直接链接，比较完整 ImportedFont、绑定/回退 metadata 与原始 bytes。纯值宿主 fixture 不创建 Rinf ingress，不提供 V1 ABI 或真实偏好管理证据。

## 实际所有权与预算

SourceBody 保存 ImportedFont 的 owned hash/label、SourceMetadata、受信 root 和字体 buffer 的 tail 范围。SourceMetadata 保存二进制 profile UUID、revision、LegacySlot 版本、完整已判定 binding/hash/reason、原 family/实际 family/runtime source、原始捕获槽 hash/label、fallback reason；资源 reference 以借用投影提供，不隐式复制 family/hash。未知 namespace 原值仍由 D 的完整 settings/frozen 持有，本单元不复制整个配置树。

实际 GNU Layout：ImportedFont `48/8`，SourceMetadata `184/8`，SourceBody `264/8`；L 的完整 no-Weak owner 在零 tail 时为 `344/8`，包括实际 Grant/header/ResourceBody，不是仅 Arc 指针。

```text
source = OwnerLayout::actual<SourceBody>(root_encoded_len + font_tail_len)
       + imported_hash_len + imported_label_len
       + saved_hash_len + captured_hash_len + captured_label_len
       + raw_family_len + actual_family_len
```

全部相加、array/extend/padding 由 L 的 checked Layout 计算。声明的 font length 只有真的成为 owner tail 才计入该 allocation；无 Vec→Arc 转换、read_to_end 或临时 owned 名字/hash/index。每个 String 是 try_reserve_exact 后填充，empty 没有 backing。借用 bytes 路线先无堆计形/检查，再由 L 的进程 BYTE_LIMIT `403701760` 和 Source class 取得 Grant，才创建源与所有最终 owned copy。

File 路线先预约实际 tail 和 label 的 512-byte upper，再一次 read_exact 直写 tail，并以单字节栈缓冲确认 EOF；短读/增长为 Corrupt，实际 I/O 错误为 Unavailable。失败时尚占据的 tail 仍持额到真实 free。Std exact compiler 的 default_read_exact 仅推进借用 slice；GNU Windows File::read → Handle::synchronous_read 使用栈 IO_STATUS_BLOCK、NtReadFile/WaitForSingleObject 和原始 OS 错误，没有新 Rust buffer。文件打开、路径转码、目录/file_type 检查及平台 provider 不由此单元签证。

Source 普通 try_clone 只共享 L header，没有 Weak。copy_metadata/copy_font_bytes 取得各自 Reply Grant 后创建独立 owner。Source/frozen holder/metadata/send 的 24 种释放顺序逐笔核对原 Layout；所有内层 backing 与 header 真 dealloc 后才返额。取消、allocator null、读取失败、hash 不匹配、epoch 失效不会提前返还活 owner。该证据不是 Dart GC/finalizer 的最后根证明。

## 父借用 capture/root 接缝

建议应用私有同步接口，不修改公开 storage/V1/Auth/trust：

```rust
fn with_terminal_font_capture<R>(
    &self,
    capture: impl FnOnce(u64, Option<&ImportedFont>) -> R,
) -> R;

fn with_source_root_font_capture<R>(
    &self,
    capture: impl FnOnce(&Path) -> R,
) -> Result<R, NumericReject>;
```

第一接口由偏好锁同时保护当前槽与单调版本，闭包持借用到本单元完成 grant/copy；不得先 preferences.get() clone。更新创建新版本，旧 Prepared/运行 owner 仍持旧 Source。第二接口由受信平台 provider 持有 root，不能接收 Dart 任意文件路径，也不能为了 capture 全局枚举字体或创建 ConfigurationSnapshot。父必须给 provider 原 PathBuf/backing 的初始 grant 与最后 root，不能把平台 provider 调用前的分配记零。

capture_file 的 File 由父按受信 root 和规范 hash 打开，当前位置为起始位置，captured_len 来自同句柄 metadata；打开/构造文件路径之前也须由父取得其确切路径/编码临时量的 grant。Source 会独立复制 root 编码，不保留这些旧 owned path。

借旧 FontResource 时，只有 bytes/hash/label 的借用用于计形/检查，新 P1 字节另 copy 到已预约 tail；没有把旧无额度 Arc 事后贴 permit。LegacyBackingLayout 仅量旧 String 的实际 capacity、两 Atomic 的 Arc<[u8]> backing 与可能仍活旧 Vec capacity；不代替旧 resource/header/Prepared/运行管理 root 的准入与最后释放证明。旧 backing 在 copy 期间的共存、原根移除接缝仍必须由父落实。

其他平台没有 actual Layout/stdlib 源与实际审计证据，保持未证；不复制 GNU 私有数字签证。完整 SourceClosure、normal Prepare/root 接线、旧 resource 最后根及真实 VM lifetime 均不得由本单元的 standalone 测试替代。
