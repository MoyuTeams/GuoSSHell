# 字体 provider 的实际捕获接缝

本单元提供 GNU Windows 的同步缓存捕获，消费稳定 `font_source` 与 L 的真实 Grant/SharedOwner。正常 lib、Prepare、旧偏好原 backing、运行/重连与 VM 接线由父持有；本单元不签发完整 SourceClosure，不把 fixture 结果提升为 normal startup 已完成。

## 父可消费接口

`capture(proof, ledger, admission, BorrowedProfile, slot, root, cancel)` 返回稳定 `SourceOwner`。`BorrowedProfile` 只借用单个原 settings、profile UUID 和 configuration revision；父必须在整个同步调用期间持有完整 ResolvedSnapshot 的有效 decode/resolve owner，包含未知 extensions 和不下发 Dart 的 metadata。没有构造 ConfigurationSnapshot、调用偏好 getter、旧 load_by_hash 或 Vec→Arc。

父先调用 `uses_legacy_slot(settings)`：

- legacy 与明确 inherit 在偏好锁内借用一个 `BudgetedLegacySlot`，槽身份和槽版本来自同一捕获；空槽也是持版本的有效槽，不能用缺少 slot 参数代替。
- explicitCached、ExplicitFamily、Uneditable 不进入槽借用接缝；provider 不解引用传入的 slot。
- strict 小写 64-byte SHA256 与原 family 绑定规则复用 `font_source::metadata::saved_binding/valid_hash`。未知或损坏 metadata 保留原 settings，由 Source 给 nonEditable/fallback 投影；不会整份拒绝普通配置。
- ExplicitFamily 在没有 fonts 子目录或任何 blob 时也正常成功、resource=None。TTF 缺失、损坏、超 32 MiB 或不可用均采用既有 fallback 分类，保留配置与捕获槽。

`BudgetedLegacySlot::try_initial` 对新 hash/label 副本在 copy 前取得实际额度，不接管旧 ImportedFont/FontResource backing。`try_replacement` 使用旧槽版本的 checked_add；构造失败保留旧槽。父在同一偏好锁内串行创建并发布下一版，不能用 configuration revision 代替槽版本。槽不是第二字体缓存、资源 registry 或另一套持久化配置。

`BudgetedCacheRoot::try_init_for_caller(grant, path, root_open_upper, open)` 只在已取得完整 root 额度后复制 path 和调用 open。父提供受信**数据目录**（其缓存为 fonts 子目录）、确切 path/handle 身份与 root-open 源模型；路径不是 Dart 输入。root-open 闭包须只返回对应目录的唯一 File，不能让额外 holder/临时 allocation 逃出 root。目录 metadata 必须是 directory 且不是 reparse point。根 path 的原 backing 必须仍有父原数据根的有效额度，本函数不事后为旧 path 补签。

`root.borrowed()` 同步保持目录句柄、path tail 和其真实 Grant。Source 会独立复制受信 root 编码，不向 Dart 投影 root、credential、path 或 note。root-open 的 `root_open_upper` 是父待核对的实际调用闭包输入，不是本 leaf 签发的生产证书；不能填写猜测常数、空白零或观测峰值。

## 前置许可、相对打开与最后释放

provider 只有两个准入关口，不能混淆：

1. **open/path 关口**：由 `ResourceContract::actual` 得到完整 `ReadWrapper` Layout，先取得 Source Grant，然后 fallible alloc，再生成固定 `fonts\\<64 lowercase hash>.ttf` UTF16 相对名。此额度拒绝时，实际 open=0、owned path copy=0、font copy=0，allocator 无事件。
2. **font tail/read 关口**：文件打开后捕获同一句柄的 metadata，调用稳定 `capture_file` 在 read/metadata 字符串 copy 前取得它自己的 Source Grant。此额度拒绝时，已有一次经准入的 open，wrapper/句柄仍持其原 Grant，关闭并 free 后才退额；不能把这种拒绝称为零 open。

不修改 `font_source/source.rs`，不绕过其 private owner 字段或复制 Source 算法。Source 的实际 hash/typeface/name/全输入检查仍走已稳定的九表 inspection 与 Source 捕获代码。

相对打开使用 `NtCreateFile`，RootDirectory 为借用目录句柄，FILE_OPEN 只打开既有文件，FILE_GENERIC_READ 只读，FILE_SHARE_READ 禁止写/删共享。OBJ_DONT_REPARSE 拒绝 fonts 中间分量或文件重解析；FILE_OPEN_REPARSE_POINT 与最终 attributes 判定同时限制 final leaf。名字是固定 74 个 UTF16 unit，只有 ASCII 常量与已验证 hash，不包含 NUL、分隔符注入或上级分量。无需 PathBuf/OsString、宽字串 Vec、路径规范化或外部文件发现。父必须保证 root 本身的真实来源与路径身份，不将任意外部目录封为 trusted。

metadata 使用同句柄的 `GetFileInformationByHandle`，固定栈输出，不构造 std 路径 metadata 或 owned I/O 错误。读取由 Source 在已预约 tail 中 read_exact，并以额外一个栈 byte 检查 EOF。读前/读后 volume、file index、attributes、length、last-write 必须一致；变化为 Corrupt，实际 metadata I/O 失败为 Unavailable。正常写入/删除句柄在捕获期间被共享模式阻断；这不是 OS/page-cache 或任意网络文件系统内容一致性的硬保证，全输入 SHA256 仍是内容身份的最终判定。

OpenLoan 的真实顺序是 File close → 原 wrapper Layout dealloc → Grant return。Source、其普通 clone、独立 metadata/send owner 与父 frozen/attempt root 分别按真实 last holder 生命周期计费；Complete、Start、ACK、slot 替换或控制 epoch 失效均不能代替释放。provider 不持有旧无额度 Arc，不使用 LegacyBackingLayout 事后补签。

## GNU 实际模型与来源

构建前件复用稳定 `FontBuildProof`：Rust 1.98.1，commit `48a229ceaefd4985c50990b14116b6d856af0985`，x86_64-pc-windows-gnu，实际 parser/hash features 仍由父核对。它不自动证明父 root-open、旧 preferences 或完整 normal Source。

实际最终类型：File `8/8`；Option<File> `16/8`；FileIdentity `32/8`；ReadWrapper `200/8`，含固定 74-unit filename，只有这一笔 provider heap allocation。不是把固定 wrapper 成本填成零。root 与 slot 使用 L 的实际 OwnerLayout 计算，不另建 heap Loan/OperationRoot。

```text
Lopen = Layout::new::<ReadWrapper>() = 200/8
Lroot = OwnerLayout::actual::<RootBody>(root_encoded_len) + root_open_upper
Lslot = OwnerLayout::actual::<SlotBody>(0) + hash_len + label_len
Pcapture = 仍活的父原数据根 + root + captured_slot + Lopen + Lsource
```

root/slot 字符串路径由本单元保留的实际 tail 或 exact String backing 构造，Grant 先于所有新 owned copy；原偏好/root backing 的 owner 并未因这些新副本而获得签证。稳定 Source 的 ImportedFont `48/8`、SourceMetadata `184/8`、SourceBody `264/8`、零 tail owner `344/8` 均不变；Source/metadata/send 的额外字符串与 tail 仍由其实际模型计算。

源锚点（只读取证，没有复制依赖源码）：

- 锁定 compiler 的 `library/std/src/os/windows/io/raw.rs`，`FromRawHandle for fs::File` 只组合 OwnedHandle/sys File wrappers。
- 同 commit 的 `library/std/src/os/windows/io/handle.rs`，OwnedHandle 为 repr(transparent) RawHandle，关闭通过 CloseHandle，无独立 Rust backing。
- 同 commit 的 `library/std/src/sys/pal/windows/handle.rs`，Handle 是 OwnedHandle wrapper；read→synchronous_read 只有栈 IO_STATUS_BLOCK、NtReadFile/WaitForSingleObject 与 raw OS 错误；没有新 Rust 字节 buffer。
- 同 commit 的 `library/std/src/sys/fs/windows.rs`，File 仅持 Handle；本 provider 不调用 std OpenOptions 的路径转换链。read_exact/固定名字/hash/Source owner 的源码与实际 layout 证据沿稳定 `font_source/边界.md`。
- Microsoft 的 `NtCreateFile`、`GetFileInformationByHandle`、OBJECT_ATTRIBUTES 与 BY_HANDLE_FILE_INFORMATION ABI：root-relative name、同步 FILE_OPEN/共享模式、重解析限制以及固定 by-handle metadata 输出。FFI 声明不是第三方实现副本。
- L 的 `resource/ledger.rs` 与 `resource/owner.rs`：真实进程账本、checked Layout、fallible backing 与 no-Weak 最后释放顺序。

## 父串行接线与尚未获证范围

最小父改动面是 `keys.rs` 的应用私有偏好状态和借用方法、`fonts.rs` 的 terminal apply/reset mutator，以及父持有的 settings/profile_fonts/prepare 接线，不需要 storage 公共 API、schema、权限或依赖变更：

```rust
fn with_terminal_font_capture<R>(
    &self,
    capture: impl FnOnce(&BudgetedLegacySlot<'static>) -> R,
) -> R;
```

方法只在原偏好锁内借用；该锁保护 current terminal slot、单调 version 及对应已收费元数据 owner。terminal apply/reset 只有成功发布新偏好时才发布相应新版本，失败保持旧值/版本；旧 mobile/V1 即时能力与 preview 不全局 apply 的规则保持。父必须覆盖初始偏好读取/解码及原 metadata backing 的有效预算根，不能先 `.get()` clone，再将 clone 交给此接口。传入 provider 的 slot 已持自己的有效 Grant，不要求保留旧 FontResource Arc。

正常 Prepare 应从已收费完整 selected snapshot 借用原 settings，按 mode 决定是否进偏好锁，同步执行 capture，随后将返回的真正 Source 移交 Prepared。Start/reconnect/attempt、完整原 metadata、writeReply 和 VM peer 继续由父及相应 leaf 保根。当前仍未获签：normal 平台 root-open 的完整源闭包和原 path/prefs backing、偏好借用/原 mutator 的实际同锁单调版本、normal Prepare/运行/VM 接线，以及 macOS/Linux 等其他 target 的相同闭包。Windows 的 isolated provider 不代替这些验收，也不是其他 target 的永久 dummy/reject 实现。

## 独立执行证据

`native/hub/tests/selected_p1_font_provider.rs` 使用每轮唯一 FontsRepo 与真实仓库两份 Meslo TTF、完整 glyf/cmap 合成字体、真实只读 fixture repository/profile。allocator/counter/probe 仅存在于独立 test executable；生产 main 没有 global allocator 或额外 heap 限制。

覆盖系统字体无缓存成功、legacy/inherit/explicitCached、unknown/nonEditable、缺失/损坏/超限/非法 hash、槽替换与 reset 后旧 Source identity、版本溢出、open 前拒绝零事件、tail 准入失败实际清理、allocator null/取消、捕获长度短读/增长、真实写/删共享阻断、非法根、目录 blob、根/文件及 fonts 中间分量 junction 边界、Source/clone/metadata/send 的 24 种释放顺序。长度变化测试注入 metadata 长度，真实 read 使用 provider 打开的 File；不把这种测试冒称任意并发文件系统实测。junction target 也仅在本轮 run 中，先精确删除 junction 再删除本轮 run，不接触用户字体或配置。

逐笔 alloc/dealloc/Layout/当时已持 Grant 审计用于证伪漏项，数学 Layout 与有限无辅助分配源码才是 before-allocation 模型，不以观测峰值决定生产常数。真实 VM/finalizer 与三桌面完整启动未在此 executable 验证。
